# ТЗ: вёрстка лендинга AdMirra из макета Figma

Самодостаточный документ для сессии вёрстки. Макет — в Figma (ссылку даёт пользователь в чате). Работаем через Figma MCP: `get_screenshot` / `get_design_context` по секциям, `download_assets` для экспорта картинок.

## 0. Что уже готово — НЕ переделывать

Каркас лежит в `landing/`:
- `index.html` — **готовый `<head>`** (title, description, canonical, OG/Twitter, JSON-LD с тарифами — всё финальное из SEO-ТЗ) и **скелет секций с уже расставленными H1/H2/H3**. В комментариях каркаса — подсказки по каждой секции.
- `assets/style.css` — CSS-переменные (цвета уточнить из Figma-переменных макета), заготовка `@font-face`.
- `assets/main.js` — заготовки аккордеона и бургера.
- `robots.txt`, `sitemap.xml` — готовы, не трогать.

**Запрещено менять:** содержимое `<head>`, тексты H1/H2/H3, их уровни и порядок. Это финальные SEO-тексты. Вёрстка наполняет секции ВОКРУГ этих заголовков.

## 1. Стек и файлы

Чистая статика: HTML + CSS + vanilla JS. Без Vue, без сборщиков, без CDN-зависимостей (шрифты и скрипты — только локальные файлы).

```
landing/
  index.html            ← единственная страница
  assets/style.css      ← все стили (можно разбить на 2-3 css при желании)
  assets/main.js        ← минимальный JS (аккордеон/бургер уже есть)
  assets/fonts/*.woff2  ← шрифт из макета (regular/medium/semibold/bold — какие реально используются)
  assets/img/*.webp     ← экспорт из Figma
  og/og-cover.png       ← сделается позже, не блокирует
```

## 2. Работа с Figma MCP — порядок

1. `get_metadata`/`get_screenshot` всего фрейма — понять состав секций.
2. Секция за секцией: `get_design_context` (даст размеры, цвета, шрифты, отступы) → вёрстка → сравнение со скриншотом.
3. Цвета/радиусы/типографику снять с Figma-переменных и положить в `:root` style.css (заготовка уже там).
4. **Ассеты**: моки дашбордов, маскот-лис, иконки карточек, логотипы интеграций — `download_assets`. Растровые моки — WebP, 2x от отображаемого размера. Логотипы интеграций и простые иконки — SVG.
5. Шрифт: определить семейство из макета, скачать woff2 (regular + используемые начертания), положить в `assets/fonts/`, прописать в `@font-face` (там уже стоит `font-display: swap` — сохранить).

На мобиле — бургер.
2. **Hero**: H1 (в каркасе) с инлайн-иконками каналов, подзаголовок, CTA «Подключить кабинеты» → `/register` + плашка «14 дней бесплатно — настройка за 5 минут · без выгрузок в Excel», два чипа-бейджа, большой мок планшета с дашбордом + летающие карточки. **Мок hero — БЕЗ `loading="lazy"`** (это LCP), с явными width/height.
3. **Для кого** (`#for-whom`): 3 карточки (Рекламным агентствам / Специалистам по контексту и таргету / Инхаус-командам). Названия — `<strong>`, НЕ h-теги.

## 4. Обязательные правила (SEO-ТЗ, нарушение = переделка)

- Ровно **один `<h1>`**; иерархия H2→H3 без перескоков (уже задана каркасом).
- Каждый содержательный `<img>` — осмысленный `alt` (подсказки в каркасе); декоративные — `alt=""` + `aria-hidden="true"`.
- Всем картинкам — `width`/`height`; всем, кроме hero-мока, — `loading="lazy"`.
- Растровые — WebP; логотипы/иконки — SVG (инлайн-SVG — `aria-hidden="true"`).
- Шрифты локально, `font-display: swap`, `preconnect` не нужен (нет внешних CDN).
- Мобильная версия содержит весь контент десктопа (mobile-first индексация). Брейкпоинты: ~1200 / 768 / 480.
- Никакого текста «в фоне» и скрытых ключевиков.
- Ориентиры производительности: LCP < 2.5s, CLS < 0.1 (width/height + отсутствие поздних вставок это дают).
