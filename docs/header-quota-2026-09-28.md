# Остаток AI в шапке и письма регистрации — 28.09.2026

## Причина и исправление

Header.vue содержал начальные aiLimit=30 и aiRemaining=30, а также такие же
fallback при отсутствии полей ответа. Шапка локально хранила подписку. Переход
между MainLayout (дашборд/AI) и MockupLayout (интеграции/проекты) пересоздавал её:
до ответа billing/subscription снова отображалась заглушка 30, при ошибке —
оставалась. Это не операция списания запросов.

Теперь используется общий in-memory snapshot, привязанный к user.id:

- При переходах сохраняются подтверждённые сервером значения. До первого
  успешного ответа показано «—», а не выдуманный лимит.
- Успешный ответ переиспользуется 30 секунд, параллельные чтения объединяются.
  Существующий фоновый refresh раз в минуту сохранён; запрос ограничен 15 секундами.
- Событие admirra:ai-usage-changed и изменение списка проектов обновляют данные
  принудительно. Если событие пришло во время чтения, выполняется ещё одно чтение;
  более ранний ответ не публикует уже устаревшее значение.
- При ошибке остаётся последний успешный snapshot; tooltip сообщает о проблеме.
- Logout/account switch немедленно очищает snapshot, запоздалые ответы другого
  аккаунта игнорируются. Лимиты не сохраняются в localStorage.
- Начисления, списания, тарифы, API и данные пользователей не менялись.

**noreply@admirra.ru**, ключ Unisender настроен (значение не выводилось).

- Email-регистрация: «Подтвердите регистрацию — AdMirra» со ссылкой подтверждения
