# Проверка данных прямого экспорта

Статус: **локальный candidate, не production**. Продолжение `a2861fa`. Schema head остаётся `f13c4d5e6f70`; новой миграции нет.

## Что изменено

- Добавлен выключенный по умолчанию `DIRECT_EXPORT_FRESHNESS_GUARDS`. Требует `REPORT_FRESHNESS_GUARDS`, который, в свою очередь, требует durable tasks и delivery guards. Неверная комбинация отклоняется при старте и использовании. До включения legacy writers должны быть остановлены, необходимые окна — подтверждены durable coverage.
- Общий SQL-only planner `core/data_requirements.py` используется сохранёнными ReportDelivery и прямыми экспортами: стабильный порядок блокировок client → integration, максимум 200 проектов и 512 источников, реальные стадии и семантические настройки. Каждый включённый проект должен иметь статистический источник; наличие источника у соседнего проекта не разрешает экспорт отсоединённого проекта с неподтверждёнными фактами.
- PDF и серверный PNG, DOCX и новые HTML-ссылки проверяют текущий и предыдущий равный период. Для PDF с шестимесячной динамикой проверяется также её диапазон. Политика консервативная: проверяются все статистические источники выбранных проектов даже для отдельного шаблона канала. Период прямого экспорта ограничен 3660 днями; старые сохранённые подтверждённые снимки не перечитываются.
- Проверка покрытия и сборка чисел проходят в отдельной Session одной SQL-транзакции. Исходные клиентские/интеграционные блокировки удерживаются до завершения чтения; доступ перепроверяется перед возвратом. Эта Session закрыта до WeasyPrint/DOCX/PNG/создания внешней ссылки. Caller Session не коммитится/не откатывается этим кодом и может продолжать собственную транзакцию.
- В отдельной read Session `lock_timeout=1500ms`, `statement_timeout=20000ms`; это SET LOCAL, не изменение конфигурации PostgreSQL. Занятые источники/отмена statement дают безопасный отказ без рендера. Это не общий 20-секундный deadline всего экспорта: несколько SQL и сам render требуют отдельных resource limits.
- В защищённом PDF ошибки query графика, каналов или dynamics больше не скрываются как успешный частичный документ.
- HTTP возвращает 409/no-store с понятным текстом вместо файла/ссылки при неготовности. Перед AI для GET/POST скачиваний выполняется preflight, чтобы известная нехватка данных не вызвала платную генерацию; перед capture проверка повторяется. Это **не** полноценная привязка AI-контекста к той же revision: AI может читать данные между проверками, этот отдельный пункт остаётся открыт.
- Legacy `/reports/send` получает preflight до AI/screenshot/recipient IO и не проглатывает DataNotReady основного/филиального PDF в fallback-отправку. Это не перевод legacy send в единый immutable per-recipient pipeline.
- Исправлен scope HTML-ссылки папки: frontend передаёт `folder_id`, backend применяет его. Раньше папка могла теряться и ссылка строилась по всем доступным проектам.
- Frontend распознаёт JSON-ошибку внутри Axios Blob для скачивания PDF/PNG. Размер разбираемой ошибки ограничен; HTML/большое тело/нестроковая detail не отображаются как текст сервера.

## Не закрыто этим этапом

- Прямой экспорт пока возвращает отказ, а не создаёт новую очередь массового refresh: пользователь может обновить источник или использовать подготовку через согласование. Нет автоматического повтора и новых скрытых paid/provider jobs.
- Browser PNG, который является локальным скриншотом уже открытого дашборда, не проходит через серверную генерацию и не объявляется подтверждённым снимком.
- Основная API Session авторизации может оставаться открытой; устранён отдельный источник locks во время render, но не все прежние длинные API/AI-транзакции. Тяжёлый renderer ещё не переведён в отдельный worker/202/status/download.
- Sheets/full-history, dashboard AI, assistant tools, detector и остальные consumers требуют собственной политики диапазонов/coverage. Этот код не доказывает готовность всех данных продукта.
- Общий regression/restore/mixed-load окончательного immutable artifact, реальные разрешённые end-to-end проверки и контролируемое переключение серверов остаются обязательными. Production flags/workers/schema/canary не менялись. S3 и две ночи наблюдения по-прежнему отложены, не выполнены.
