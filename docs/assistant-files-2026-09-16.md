# Файлы в AI ассистенте

## Реализация

- Кнопка «Файл» в обоих полях ввода. PDF, DOCX, TXT, MD; до 3 файлов в сообщении, 25 МиБ на файл, 40 000 символов извлечённого текста. Лимит увеличен с 8 МиБ по просьбе владельца. Окно загрузки 90 с на сервере и 120 с на клиенте; парсер по-прежнему ограничен 12 с.
- PDF: только текстовый слой, не OCR; максимум 100 страниц, зашифрованные документы отклоняются. Из DOCX читается основной текст, включая таблицы, без изображений, колонтитулов и встроенных объектов. TXT/MD: UTF-8 или UTF-16 с BOM.
- Исходные бинарные документы не сохраняются. Текст и метаданные хранятся в существующей `ai_messages` с ролью `attachment`. Пользовательское сообщение ссылается на них через `tool_calls.attachments`. Для role=user это метаданные, не вызовы инструментов. Миграция схемы не нужна.
- Непосланные вложения восстанавливаются при открытии диалога, их можно убрать. Уже использованные документы сохраняются с историей и удаляются вместе с диалогом. Добавлена кнопка удаления диалога с подтверждением. Срок хранения — до удаления диалога; автоматического TTL нет. Резервные копии БД подчиняются общей политике хранения.
- Лимит диалога: 20 документов и 120 000 символов. На пользователя: максимум 100 сохранённых загрузок за последние 24 часа и 1000 всего. Это ограничения хранимых данных, не защита от всех видов злоупотребления запросами. Извлечение: максимум 2 одновременных процесса на процесс API, CPU 8 с, timeout 12 с, RAM 384 МиБ в Linux. ZIP — до 1000 записей / 20 МиБ распакованного содержимого; DTD/ENTITY не допускаются.
- Парсер запускается без окружения приложения/секретов во временном каталоге; это ограниченный subprocess, не полноценная ОС-песочница с сетевой изоляцией. Процесс не обращается к URL из документов. Исходные байты не публикуются через uploads.
- Каждая операция проверяет текущего пользователя и владельца диалога; attachment ID дополнительно ограничен тем же диалогом. История включает текст только использованных файлов, один раз на файл. Инструкции из файлов рассматриваются как недоверенные данные. Защита от prompt injection не является абсолютной гарантией; реальные права обеспечиваются инструментами на сервере.
- Текст вложений отправляется действующему LLM-провайдеру вместе с запросом и расходует его токены. Исходные бинарные файлы туда не отправляются.
- Под сохранённым ответом — DOCX и MD. Экспорт только собственного сохранённого финального ответа, не arbitrary HTML/URL. MD сохраняет оригинал. DOCX поддерживает обычные заголовки, жирный текст, списки, таблицы до 8 столбцов, блоки кода и текстовые ссылки. Более широкие таблицы выводятся строками без потери значений. Это не полный типографский рендер всех расширений Markdown/LaTeX.
- Экспорт выполняется без повторного запроса к ИИ. Файл формируется в памяти, `Content-Disposition: attachment`, `Cache-Control: private, no-store`, `nosniff`. Публичных постоянных ссылок нет.

## Проверки

- `tests/test_assistant_files.py`: 17 проверок парсинга, лимитов, прав, истории, удаления, экспорта и передачи вложений в агент. Запущены на действующем backend image в изолированном контейнере, `--network none`, SQLite, без production env/БД/LLM.
- Frontend production build успешен. Браузерный изолированный mock API: загрузка → сообщение с attachment ID → SSE → download на 1440 и 390 px, без ошибок JS и горизонтального overflow.
- Тестовый DOCX отрисован bundled LibreOffice, страница проверена визуально.

## Точечный релиз и откат

База production checkout: `cdf0a4d`. Нельзя выкатывать весь локальный HEAD: там отдельно подготовлены незавершённые DevOps-изменения.

`ops/assistant-files/Dockerfile.backend` накладывает только `files.py`, `router.py`, `agent.py` на точный действующий backend image. `Dockerfile.frontend` накладывает собранные assets и index.html на действующий frontend image, сохраняет лендинг и остальные статичные файлы. Фронт собирается из чистого архива `cdf0a4d` с двумя новыми Vue-файлами. Незакоммиченные изменения MainLayout, SignIn, landing исключены.

`deploy.py` сохраняет root-only standalone Compose snapshot, пинит образы и точные runtime environment backend/frontend. `.env`, nginx, БД, automation, admin_frontend, почта и шлюзы не меняются. При неуспешном старте/проверке откатывает образы. Проверка HTTP запуска — `/openapi.json` и публичная главная; это не заменяет бизнес smoke test.

Важно: git checkout сервера остаётся на базовом коммите, релиз определяется ID образов и feature revision. Обычный `docker compose up --build` из старого checkout перезапишет релиз. Для следующих выкладок использовать сохранённый active.json либо сначала согласованно перенести этот feature commit в production release branch. Не запускать blanket pull/build локального DevOps HEAD.

Откат: `python3 /root/admirra-assistant-files-deploy.py --rollback /root/admirra-assistant-files-backups/<snapshot>`. При изменении env/nginx/images после выкладки автоматический откат отказывается работать, требуется ручная сверка. Тексты вложений останутся в БД, но старый интерфейс их не отобразит.
