# Приоритетные письма доступа — 24.09.2026

**Обновление:** код активирован на обоих production API 24.09 в release
`2ce9513`. Полная regression: 1639 passed; подробности в
[протоколе cutover](devops-production-cutover-2026-09-24.md).
Подтверждённое техническое письмо нового образа доставлено владельцу тестового
аккаунта; нельзя гарантировать приём несуществующим/отказавшим почтовым сервером.

Запрошенные пользователем OTP, подтверждение email и сброс пароля используют
Unisender Web API, если действующий SMTP host — smtp.go1/go2.unisender.ru.
Причина: SMTP-документация не обещает поддержку bypass-флагов в X-UNISENDER-GO.
Отправитель остаётся SMTP_FROM, тот же API key и URL из runtime config.

На уровне одного письма: bypass_global=1, bypass_unavailable=1,
bypass_unsubscribed=0, bypass_complained=0. Не удаляем списки, не обходим
локальные жалобы/отписки, не меняем отчёты, welcome, приглашения и промо.
Глобальные отметки, включая полученные другими отправителями, игнорируются;
системные запреты провайдера и отказ принимающего сервера всё равно возможны.
Чтения/переходы не отслеживаются. Это попытка приоритетной доставки, не гарантия.

HTTP success принимается только с job_id и без failed_emails. При timeout,
невалидном ответе или отказе не повторяем через SMTP: исходная отправка может
быть уже принята. Ошибки без response body, адресов, ссылок и кодов в логах.
SMTP_ENABLED=false продолжает полностью выключать отправку; другие SMTP
провайдеры работают прежним способом. Для Unisender отсутствующий API key —
явный отказ, а не незаметный возврат к старой политике.

Первоначальная проверка до релиза: 16 isolated unit tests passed на image
24f58b7 с точечным source overlay, сеть отключена. Затем выполнены полная
регрессия нового image и production rollout, указанные в начале документа.

Диагностика до изменения: SMTP AUTH 235, MAIL FROM 250, домен подтверждён,
DKIM active. Два письма одному адресу @acmind.ru — skip_dup_unreachable;
system permanent_unavailable от 29.01.2026. По поручению владельца точечно
удалена только эта запись; повторный suppression/get вернул пустой список.
Новые письма для этого пользователя не отправлялись автоматически.

Документация: https://godocs.unisender.ru/suppression-lists,
https://godocs.unisender.ru/web-api-ref, https://godocs.unisender.ru/smtp-api.
