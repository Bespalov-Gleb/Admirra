# Пакетная загрузка сводок — проверка и узкий релиз

## Границы

По просьбе владельца ожидание двух ночей и S3 отложены. Этот релиз даёт возможность проверить скорость чтения на сайте, но **не завершает полный DevOps cutover**. Новый календарь Celery, recurring billing, sync/history consumers и расширение API-2 не включаются. Схема production остаётся `cc3d4e5f6a7b` с ранее добавленным assistant ledger.

Код: `98b8ad4`, `df31bc8`, `3046293`. Из рабочего дерева не включены чужие изменения MainLayout, SignIn и landing.

## Что ускорено

- `SummaryFacts` собирает исходные суммы сразу по группе разрешённых проектов и переиспользует их только внутри одного HTTP-запроса. Страницы по 64 проекта, максимум 4 страницы/периода в памяти; при слишком большом количестве групп целей — возврат к обычному SQL без усечения данных.
- Сохранены формулы CPL, выбранные цели, VK lead action scopes, сравнение периодов и отдельная точная атрибуция при фильтре кампаний. Общие суммы папок остаются на каноническом SQL-пути.
- Новый защищённый `GET /api/dashboard/project-summaries`: до 64 проектов, четыре канала, даты/период; любой чужой ID отклоняется до расчётов.
- Карточки и строки проектов получают пакетный ответ вместо четырёх summary HTTP-запросов на проект. Данные предыдущего запроса при смене фильтра не подставляются; при недоступном batch endpoint остаётся совместимый fallback. Запросы подробностей целей пока отдельные.
- Это не Redis-кэш: сохранённые настройки/новые синхронизированные данные видны следующему запросу без TTL.

## Измерение на одинаковой восстановленной базе

Backup `20260920T190219Z-a6b49102`, изолированный контейнер API 1 CPU / 1 GiB, PostgreSQL 2 CPU / 2 GiB, внешний доступ запрещён. По 64 запроса к восьми маршрутам, конкурентность 4. Baseline `dbb3e96`, кандидат `98b8ad4`.

| Маршрут | Медиана до, мс | После, мс |
|---|---:|---:|
| `/clients/stats` | 3956,67 | 1940,77 |
| `/folders/tree` со статистикой | 4198,19 | 2354,07 |
| `/folders/top-projects` | 3737,17 | 1139,07 |

64/64 HTTP 200 в обоих прогонах. Общая длительность 26,615 → 14,995 с. Размеры и SHA-256 ответов всех восьми маршрутов совпали. Это результат изолированного испытания, а не обещание такой же задержки в браузере. Некоторые лёгкие маршруты в конкурентном прогоне стали медленнее: ускорение не заявляется для всех вкладок. Ответ списков с аватарами около 1 MiB остаётся отдельным источником задержки.

Этот benchmark не измеряет новый frontend batch API: его сверяет отдельный smoke на восстановленной базе и при выкладке.

## Артефакты и процедура

Backend overlay собирается поверх **реально работающего** `6321c5fb…`, не поверх общего DevOps candidate. Проверяются SHA-256 исходных файлов и наличие assistant quota hotfix. Копируются девять файлов статистики/схем/защиты сравнений AI-комментария и чистых env helpers; никакой общей миграции. Из предыдущих правок статистики также включено исправление двойного знаменателя Avito CPL и версия расчёта, чтобы не выдавать смену алгоритма за изменение показателя.

- Frontend `admirra-frontend:summary-df31bc8`: `sha256:019ae4025bf17f9d4412b78946ebfb4a74a2aac6628c4dde9803a1ecbb31ec80`.
- Только для тестов `admirra-summary-tests:verified`: `sha256:480ccc7c720c30e403809a60984084c5f485ea4a8c7df3aaf794ee1b9cc13da0`. Содержит startup guard и synthetic fixtures; **не выкатывать**. Собран на API-2 добавлением `core/runtime.py` и benchmark script поверх переданного test derivative `f590606…`. SHA-256 всех девяти изменённых модулей сверены с финальным production overlay и совпали.
- Frontend относительно работающего quota release `0e5f031` меняет только batch loader, его тест и два компонента карточек/строк. Тарифы, AI, landing и макет не изменены.

`ops/performance/deploy.py` проверяет текущие digests/schema, отсутствие активных sync/report и недавних AI-запросов, запрещает перезапуск рядом с 03:00/05:00 МСК. Сохраняет literal compose root-only, проверяет env/порты/тома, меняет только backend/frontend. После backend выполняет разрешённый read smoke; при ошибке возвращает оба предыдущих образа. Smoke использует только предоставленный тестовый аккаунт, сравнивает до 12 индивидуальных ответов и проверяет отсутствие доступа без авторизации/к чужому ID. Индивидуальный summary может обновить snapshot посещения этого тестового аккаунта; платежи, AI, провайдерские sync и отправки не вызываются.

После успешной выкладки здесь должны быть добавлены время, rollback directory, фактические digests, smoke и public health. До этого документ **не подтверждает выкладку**.
